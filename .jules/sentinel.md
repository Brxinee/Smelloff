## 2025-05-15 - Timing Attack in Admin Authorization
**Vulnerability:** The `isAdminAuthorized` function in `api/_security.js` compared the provided authorization token directly against the server's expected admin secret. It used a length check (`a.length === b.length`) before calling `crypto.timingSafeEqual`, meaning it returned `false` immediately if the lengths did not match. This leaked the exact length of the server's secret, enabling an attacker to discover the secret length and significantly narrowing down the search space for brute force attacks.
**Learning:** Checking lengths before using a timing-safe string comparison function defeats the purpose of the timing-safe function when comparing against a variable-length secret. While `crypto.timingSafeEqual` prevents leaking *which* character is wrong, an early length check leaks the overall length of the secret.
**Prevention:** When comparing two sensitive strings of potentially variable lengths, hash both strings first (e.g., using `SHA-256`) and then compare the resulting fixed-length hashes using `crypto.timingSafeEqual`. This ensures the comparison always takes a constant amount of time regardless of the original strings' lengths or contents.
