## 2026-10-19 - Timing Safe Equal Vulnerability
**Vulnerability:** Found multiple instances where `crypto.timingSafeEqual` was used without following the constant-time execution pattern when buffer lengths differ. In `api/admin.js`, if lengths differ, it short-circuits with a `return false`.
**Learning:** `crypto.timingSafeEqual` throws if lengths are different, but the established project pattern is to do a dummy comparison (`crypto.timingSafeEqual(a, a)`) when lengths differ, and use a boolean flag instead of returning early. Returning early or short-circuiting (`||`) leaks the fact that lengths don't match in non-constant time, which is a timing side-channel vulnerability.
**Prevention:** When comparing buffers with `crypto.timingSafeEqual` in Node.js, ensure constant-time execution by performing a dummy comparison (e.g., `crypto.timingSafeEqual(expected, expected)`) when lengths differ. Crucially, do not return early; use a boolean flag (e.g., `let isValid = false`) to ensure the overall code block always takes an identical amount of time to execute regardless of the comparison's outcome.
