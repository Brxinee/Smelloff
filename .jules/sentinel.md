## 2026-10-15 - Timing Safe Equal Vulnerability
**Vulnerability:** The constant-time string comparison (`crypto.timingSafeEqual`) was vulnerable to timing attacks when input lengths differed. The codebase pattern performed a dummy comparison (`crypto.timingSafeEqual(expected, expected)`) on length mismatch but the subsequent early return or short-circuit evaluations (`&&`) bypassed the constant-time guarantee.
**Learning:** Even with a dummy `timingSafeEqual` call, if the code path immediately returns or uses differing logic to skip the actual validation comparison, an attacker can still glean length information via timing analysis. The dummy comparison must take the exact same time as the successful comparison *and* not short circuit.
**Prevention:** Always implement the constant-time dummy comparison and ensure the overall code block executes in constant time regardless of the outcome. Store the validation result in a boolean variable and return it at the end of the check instead of returning early on length mismatch.
