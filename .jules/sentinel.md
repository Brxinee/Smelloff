## 2025-02-14 - Fix length timing attack in cryptographic comparisons
**Vulnerability:** The `crypto.timingSafeEqual` length mismatch leak is a well-known vulnerability in cryptographic comparisons. Because `crypto.timingSafeEqual` throws an error if lengths mismatch, it is often accompanied by an `a.length === b.length` check before doing the comparison. But doing so introduces a timing attack that reveals the length of `a` (the secret) by sending strings of varying length to see when the response time slightly increases.
**Learning:** Checking for equal length before `crypto.timingSafeEqual` using non-constant time comparison allows length-based timing attacks. The attacker can infer the exact length of secrets.
**Prevention:** Always hash both values (e.g., using SHA-256) before passing them to `crypto.timingSafeEqual`. This ensures both buffers are exactly the same length (e.g., 32 bytes), eliminating the length leak and bypassing the need for a non-constant time length check.
